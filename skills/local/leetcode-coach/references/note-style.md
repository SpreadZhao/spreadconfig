# Note Style

SecondBrain LeetCode notes are personal learning records. They should explain the user's path through the problem, not replace it with an official solution.

## Preserve

- Existing front matter fields such as `num`, `title`, `link`, `tags`, and `mtrace`.
- Existing TODOs.
- Manual observations.
- Obsidian links.
- Diagrams and image references.
- Failed attempts that remain useful.

## Add

- Date-specific practice records.
- Language-specific implementation notes.
- The key bug or insight from the session.
- Edge cases that changed the user's understanding.
- Short cross-language comparisons when useful.

## Avoid

- Large duplicated editorials.
- Rewriting a whole note because a small section changed.
- Splitting the same problem into language-specific note files.
- Deleting manual content that the user did not ask to remove.
